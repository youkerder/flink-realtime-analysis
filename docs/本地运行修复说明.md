# 本机无法运行：定位过程、修复方案与验证结果

> 环境：Windows 11 + 本机 `D:\projects\flink-realtime-analysis`
> 结论：**已在本机跑通并跑出正确结果**（Kafka → Flink → 列存 → 大屏），且给出两条可复现路径：
> ① Docker 形态（生产一致，需先手动启动 Docker Desktop）；② Windows 原生形态（无需 Docker/WSL，本机已实测）。

---

## 一、先看结论：到底卡在哪

| # | 现象 | 直接原因 | 是否已修 |
|---|---|---|---|
| 1 | `flink run` 报 `FileNotFoundException: realtime-analysis-1.0.jar` | 仓库 `.gitignore` 排除了 `flink-job/target/`，克隆后没有 jar，README 的「快速开始」直接从提交作业开始 | ✅ 加构建步骤 + 启动脚本自动构建 |
| 2 | `docker compose up` 起不来 / ClickHouse 连不上 | 本机 Docker Desktop 依赖 WSL2，而 `wsl.exe` 被系统安全策略禁用（沙箱层面），Docker daemon 无法启动；Windows 也没有 ClickHouse 官方构建 | ✅ 新增「Windows 原生模式」，用列存引擎 + ClickHouse HTTP 兼容层替代容器 |
| 3 | 作业显示 RUNNING，但结果表几乎没数据 | 直接回放**未排序**的原始 CSV，事件时间 + 5 秒乱序容忍会把 96% 的记录判为迟到丢弃（实测保留率 **3.94%**） | ✅ 增加排序脚本 + 一键脚本默认用排序后的数据 |
| 4 | `Unrecognized option: --add-opens` | 本机默认 `JAVA_HOME` 指向 **JDK 8**，Kafka 4.x / Flink 1.20 需要 17+ | ✅ 启动脚本自动探测并校验 JDK 版本 |
| 5 | `jdbc:clickhouse://172.31.192.1:8124` 连接超时 | 原脚本写死了 WSL 网关 IP，WSL 重启后 IP 变化 | ✅ 原生模式全走 `127.0.0.1`，不再依赖宿主 IP |
| 6 | 大屏漏斗只显示一段/标签看不清 | 结果按行刷盘被拆批，最新窗口只写入了 pv 一行；且漏斗后两级数值小被压成细线 | ✅ Sink 定时刷盘 + 幂等写入 + 图表 `minSize/label` 调整 |
| 7 | 重跑后数据翻倍 | ClickHouse/JDBC 表无去重，重启从 earliest 重放会重复写 | ✅ 本地列存用窗口主键 + `INSERT OR REPLACE` 实现幂等（等价 ReplacingMergeTree） |

## 二、逐层定位过程（怎么一步步排掉的）

### 1) 结构层
```
dashboard/  ECharts 大屏（静态页 + 5s 轮询 ClickHouse HTTP）
flink-job/  Maven 工程 → fat jar（Kafka Source / 窗口 / 漏斗 / TopN / JDBC Sink）
producer/   replay_producer.py（CSV→Kafka）
db/         init.sql（3 张 MergeTree 表）
docker-compose.yml / start-all.cmd（两套编排）
```
关键依赖：Flink 1.20.0、Kafka 3.x/4.x、ClickHouse 24.8、JDK 11+、Python 3.10+、kafka-python。

### 2) 构建层
```bash
mvn -f flink-job/pom.xml clean package -DskipTests
```
→ BUILD SUCCESS，`target/realtime-analysis-1.0.jar`（43.7 MB）。
**但 `target/` 不在仓库里**，所以任何「克隆 + 直接跑脚本」的路径都会在提交作业这步断掉。

### 3) 依赖层
- `java -version` → 默认 21，但 `JAVA_HOME` 指向 JDK 8，Maven/Kafka 都会踩到版本坑；
- `docker info` → `The system cannot find the file specified`（daemon 未启动）；
- `wsl.exe` → 被安全策略拦截，**这是本机无法起 ClickHouse 容器的根因**；
- `pip install kafka-python` → 装到了另一个 Python（3.14），默认 `python` 是 3.13，import 失败。

### 4) 数据层
全量扫描 `data/UserBehavior.csv`（100,150,807 行）发现：行序是被打散的（同一分钟的数据散落在整个 3.5 GB 文件里）。而作业用 `forBoundedOutOfOrderness(5s)`：
- 取前 30 万行直接跑窗口函数 → PV 只剩 10,618 / 应得 269,201（**3.94%**）；
- 排序后跑全量 → 13,094 个窗口，Σpv 89,661,330，与离线完全一致。

### 5) 服务层
Kafka 4.3.1 原生启动正常（`kafka.Kafka` + `--add-opens`），topic 3 分区，回放 20 万条 0 失败。
Flink 1.20.5 Windows 发行版**没有 `.bat` 启动脚本**，用 `java -cp "lib/*"` 跑本地模式可用（JDK 17 需补 `--add-opens`）。

## 三、修复方案

### 3.1 核心思路
生产形态（ClickHouse + JDBC Sink）保持不变；额外提供一条**只替换"存储落地"这一层**的本机路径：

```
CSV → Kafka → Flink(事件时间窗口/漏斗/TopN) → HttpResultSink
                                                │ ClickHouse HTTP 协议(JSONEachRow)
                                                ▼
                            tools/ch_http_server.py（DuckDB 列存 + 大屏静态服务）
                                                │ /clickhouse/?query=... FORMAT JSON
                                                ▼
                                          ECharts 大屏（不改一行）
```
- 作业侧只加了 `--sink http --store <url>` 两个参数，默认仍是 `jdbc`，**不影响原有生产链路**；
- 大屏侧完全没改 SQL，因为兼容层实现的就是 ClickHouse 的 HTTP 查询接口（含 `FORMAT JSON`）；
- 本地存储用 DuckDB（列存、零安装、Windows 原生），建表结构、排序键语义与 `db/init.sql` 对齐，并加主键做幂等。

### 3.2 改动清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `flink-job/.../HttpResultSink.java` | 新增 | ClickHouse HTTP + JSONEachRow 写入；批量 300 行/500ms；定时刷盘线程（解决数据流暂停时尾部不落库）；失败保留缓冲重试，不把作业打挂 |
| `flink-job/.../RealtimeAnalysisJob.java` | 修改 | 新增 `--sink jdbc|http`、`--store` 参数；三条结果流按模式分支；新增三个 `xxxToJson` 方法（时间统一按东八区格式化，规避时区偏移） |
| `tools/ch_http_server.py` | 新增 | ClickHouse HTTP 兼容层 + 大屏静态服务（同一端口 8090，天然无跨域）；DuckDB 建表带主键，`INSERT OR REPLACE` 幂等；支持 `TRUNCATE`、`/stats` 自检 |
| `tools/native_up.py` | 新增 | 一键启动：校验 JDK≥17 → 构建 jar → 起 Kafka → 建 topic → 起兼容层/大屏 → 起作业 → 可选回放；日志落 `runtime/logs/`，前台托管可 Ctrl+C 全停 |
| `tools/sort_dataset.py` | 新增 | 外部归并排序，把原始 CSV 按事件时间排好（4 分钟 / 1 亿行） |
| `dashboard/index.html` | 修改 | 漏斗 `minSize:12%`、`gap:4`、标签白字内置，解决后两级被压成细线 |
| `README.md` | 修改 | 补充「形态 C：Windows 原生」章节与数据排序要求 |

> 说明：`HttpResultSink` 与兼容层是**为无 Docker 环境增加的适配层**，不改变项目的技术叙事（Flink 作业、窗口语义、指标口径原样保留）。有 Docker 的机器仍然走 `docker compose` + JDBC + 真 ClickHouse。

## 四、操作步骤（Windows 原生模式，本机已验证）

### 4.1 环境依赖
| 组件 | 版本 | 本机实际 |
|---|---|---|
| JDK | **17+**（Flink 1.20 / Kafka 4.x 要求） | Microsoft OpenJDK 17.0.8 |
| Maven | 3.6+ | 3.9.16 |
| Python | 3.10+ | 3.14（需装 `kafka-python`、`duckdb`） |
| Kafka | 4.x（KRaft） | 4.3.1（`runtime/kafka_2.13-4.3.1`） |
| Flink | 1.20.x | 1.20.5（`runtime/flink-1.20.5`） |
| 数据 | 天池 UserBehavior.csv | 100,150,807 行 / 3.5 GB |

```bash
python -m pip install "kafka-python>=3.0" duckdb
```

### 4.2 准备数据（只需一次）
```powershell
# 1) 全量校验数据（可选，5 分钟）
python tools/verify_dataset.py --file data/UserBehavior.csv

# 2) 按事件时间排序（关键！否则丢 96% 记录）
python tools/sort_dataset.py --file data/UserBehavior.csv --out tools/UserBehavior.sorted.csv
```

### 4.3 一键启动
```powershell
cd D:\projects\flink-realtime-analysis
python tools\native_up.py --reset --replay 5000000
```
脚本会依次：校验 JDK → 构建 jar（缺失时）→ 起 Kafka(9092) → 建 topic → 起兼容层+大屏(8090) → 清表 → 起 Flink 作业 → 回放 500 万条。
**保持该窗口打开**，Ctrl+C 可一次性停止全部组件；加 `--detach` 则后台运行。

启动成功的输出：
```

[1/4] 作业 jar 已存在: flink-job\target\realtime-analysis-1.0.jar
[2/4] Kafka 已在运行 (9092)
[3/4] 大屏 / ClickHouse 兼容层已在运行 (8090)
[4/4] 提交 Flink 作业（本地模式，sink=http）...
  大屏      : http://localhost:8090
```

### 4.4 等价的单步命令（便于理解/排查）
```powershell
# 构建
mvn -f flink-job\pom.xml clean package -DskipTests

# Kafka（Windows 原生，注意用 java -cp 而不是 .bat，否则命令行超长）
$J="C:\Program Files\Microsoft\jdk-17.0.8.7-hotspot\bin\java.exe"
& $J --add-opens=java.base/java.nio=ALL-UNNAMED -Xmx1g -cp "libs/*" kafka.Kafka config/verify.properties   # 工作目录 runtime\kafka_2.13-4.3.1
& $J --add-opens=java.base/java.nio=ALL-UNNAMED -cp "libs/*" org.apache.kafka.tools.TopicCommand --bootstrap-server localhost:9092 --create --if-not-exists --topic user_behavior --partitions 3 --replication-factor 1

# ClickHouse 兼容层 + 大屏
python tools\ch_http_server.py --port 8090 --db runtime\warehouse.duckdb --dashboard dashboard

# Flink 作业（本地模式）
& $J -Xmx4g --add-opens java.base/java.util=ALL-UNNAMED --add-opens java.base/java.lang=ALL-UNNAMED `
  --add-opens java.base/java.nio=ALL-UNNAMED --add-opens java.base/sun.nio.ch=ALL-UNNAMED `
  -cp "runtime\flink-1.20.5\lib\*;flink-job\target\realtime-analysis-1.0.jar" `
  com.example.realtime.RealtimeAnalysisJob --kafka 127.0.0.1:9092 --sink http --store http://127.0.0.1:8090/clickhouse/

# 回放
python producer\replay_producer.py --file tools\UserBehavior.sorted.csv --bootstrap 127.0.0.1:9092 --topic user_behavior --rate 0 --limit 5000000
```

### 4.5 有 Docker 的机器怎么跑（生产一致）
```bash
mvn -f flink-job/pom.xml clean package -DskipTests     # 必须先构建
docker compose up -d
docker exec kafka kafka-topics.sh --bootstrap-server localhost:9092 --create --topic user_behavior --partitions 3
docker exec jobmanager flink run -c com.example.realtime.RealtimeAnalysisJob \
  /opt/flink/usrlib/realtime-analysis-1.0.jar --kafka kafka:9092 --clickhouse "jdbc:clickhouse://clickhouse:8123/rt"
python producer/replay_producer.py --file data/UserBehavior.sorted.csv --rate 0 --bootstrap localhost:9094
```
> 前提：先把 Docker Desktop 启动起来（本机因 `wsl.exe` 被禁用起不来，这一步需要你在自己的环境里操作）。

## 六、与原版的差异 / 边界（面试时也要能说清）

| 项 | 原版（Docker） | 本机原生模式 |
|---|---|---|
| 消息队列 | Kafka 容器 | Kafka 原生进程（同一版本 4.3.1，协议一致） |
| 计算 | Flink standalone 集群 | Flink 本地模式（算子、窗口、Watermark、状态完全同一套代码） |
| 结果存储 | ClickHouse 24.8（MergeTree） | DuckDB 列存 + 自建 ClickHouse HTTP 兼容层（表结构/排序键对齐，主键幂等） |
| Sink | `JdbcSink`（JDBC） | `HttpResultSink`（ClickHouse HTTP + JSONEachRow） |
| 前端 | Nginx 反代 | 兼容层直接托管静态页（同源，无跨域） |
| 差异点 | — | 不验证 ClickHouse 的 MergeTree 合并、ReplacingMergeTree、集群分片等特性；`FORMAT JSON` 等接口为子集实现 |

**结论**：本机模式验证的是「数据链路 + 计算逻辑 + 展示」，不是 ClickHouse 引擎本身。要验证 ClickHouse 相关能力（物化视图、ReplacingMergeTree、查询性能），仍需 Docker/Linux 环境跑原版。

## 七、常见问题

| 报错 | 原因 | 处理 |
|---|---|---|
| `Unrecognized option: --add-opens` | 用了 JDK 8 | 安装 JDK 17，`native_up.py` 会自动挑；手工启动时显式用 JDK17 的 java.exe |
| `Address already in use: bind 9092/8090` | 上次进程没退 | `taskkill /F /IM java.exe`（会杀掉所有 java，注意别误伤）或按 `runtime/pids/*.json` 里的 pid 精准 kill |
| 大屏 `数据加载失败: ClickHouse 502` | curl/浏览器走了系统代理 | 访问时绕过代理：`curl --noproxy '*'`；浏览器把 `localhost` 加入代理例外 |
| `DuckDB ... write-write conflict` | 同库被两个兼容层进程打开 | 只保留一个 `ch_http_server.py` 进程 |
| 窗口只有 3~4% 的数据 | 回放了未排序的 CSV | 先跑 `tools/sort_dataset.py` |
| 结果表为空但作业 RUNNING | Kafka 无数据 / topic 名不一致 | 检查 `replay_producer.py --topic` 与作业 `--topic` 是否都是 `user_behavior` |
