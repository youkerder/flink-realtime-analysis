# 项目文件说明

仓库当前跟踪 **38 个文件**，本文逐个说明它们的职责、所属链路环节，以及是否还有用。

标记约定：

| 标记 | 含义 |
|---|---|
| ✅ | 核心文件，跑通链路必需 |
| 🔧 | 辅助工具（运维、验证、兼容层） |
| 📦 | 历史遗留，保留仅作参考，新流程不依赖 |

数据流视角先建立起来，后面的文件都能对号入座：

```
producer/ ──► Kafka ──► flink-job/ ──► ClickHouse ──► dashboard/
（造数/回放）          （窗口/漏斗/TopN）   （结果表）      （大屏）
                ▲                          ▲
                └──── docker-compose.yml / start-all.* / tools/native_up.py（编排启动）
```

## 一、根目录：入口与编排（10 个）

| 文件 | 作用 | 标记 |
|---|---|---|
| `.gitignore` | 排除不该入库的内容：`data/*.csv`（3.5 GB 数据集）、`flink-job/target/`（构建产物）、`runtime/`（Kafka/Flink 发行包与日志）、`tools/*.csv` 等本机运行产物、`.backup-*/` | ✅ |
| `README.md` | 项目主文档：架构图、功能指标口径、技术要点、性能实测、三种运行形态、数据集说明 | ✅ |
| `docker-compose.yml` | **形态 B（全容器）**：kafka + jobmanager + taskmanager + clickhouse + dashboard(nginx) 五个服务的编排，含端口映射、健康检查、初始化 SQL 挂载 | ✅ |
| `start-all.cmd` | **形态 A 的 Windows 入口**：以隐藏窗口启动 WSL 里的 `start-all.sh`，轮询 `8081/overview` 等集群就绪，清空三张结果表，提交 Flink 作业，再拉起 ClickHouse/大屏容器 | ✅ |
| `stop-all.cmd` | 形态 A 的停止入口：写 `~/stop_flag` 通知 WSL 锚点自杀，再 `docker compose stop` 停容器 | ✅ |
| `start-all.sh` | **WSL 内的自愈锚点**：死循环探测 9092（Kafka）与 8081（Flink），掉线自动重启；检测到 `~/stop_flag` 时优雅停止并退出。这样关掉终端也不影响集群 | ✅ |
| `stop-all.sh` | WSL 内手工停止：`bin/stop-cluster.sh` + `pkill kafka.Kafka`（`stop-all.cmd` 不直接用它，走的是 stop_flag 机制） | 🔧 |
| `anchor.sh` | 更早版本的一次性锚点：起 Flink → 提交作业 → `sleep infinity`。功能已被 `start-all.sh` 覆盖 | 📦 |
| `pipeline_up.sh` | 幂等拉起脚本：Kafka 未起则起、Flink 未起则起、**没有 RUNNING 作业时**才提交，最后打印作业列表。适合反复执行 | 🔧 |
| `flink-supervisor.sh` | 只做探活重启（每 20s 检查 Kafka/Flink），不含提交作业逻辑；是 `start-all.sh` 拆分前的版本 | 📦 |

> `.cmd` 与 `.sh` 是一对：`.cmd` 负责 Windows 侧（Docker Desktop、窗口），`.sh` 负责 WSL 侧（Kafka、Flink）。

## 二、flink-job/：计算核心（5 个）

| 文件 | 作用 | 标记 |
|---|---|---|
| `pom.xml` | 构建定义：Flink 1.20（`provided`，集群已带）+ `flink-connector-kafka` 3.3.0-1.20 + `flink-connector-jdbc` + `clickhouse-jdbc`（all）+ `jackson-databind`；`maven.compiler.release=11`；shade 插件打成 `realtime-analysis-1.0.jar` | ✅ |
| `RealtimeAnalysisJob.java` | **主作业**。装配 KafkaSource 与水位线策略；两条计算支路——① `windowAll` 1 分钟滚动窗口算 PV/UV/四类行为/三级漏斗，② `keyBy(itemId)` 增量聚合 + `keyBy(windowStart)` + 事件时间定时器算 TopN；三条 Sink（`--sink jdbc` 或 `--sink http`）；结果行转 JSONEachRow | ✅ |
| `UserBehavior.java` | 事件 POJO：`userId / itemId / categoryId / behavior / timestamp`（秒级）。有 public 无参构造 + getter/setter，满足 Flink POJO 序列化条件（不走 Kryo） | ✅ |
| `UserBehaviorDeserializer.java` | Kafka 消息 → `UserBehavior` 的反序列化器，同时承担**脏数据过滤**：行为类型白名单（pv/cart/fav/buy）+ 时间戳范围校验（2017-11-25 ~ 12-04），不合法就静默丢弃（避免抛异常触发重启风暴） | ✅ |
| `HttpResultSink.java` | 通过 ClickHouse **HTTP + JSONEachRow** 协议写结果表的 Sink。批量 300 行/500ms，带定时刷盘线程（数据流暂停时尾部也能落库），失败保留缓冲区重试、不把作业打挂。用于没有 ClickHouse 服务端的本机环境 | 🔧 |

## 四、db/：存储定义（2 个）

| 文件 | 作用 | 标记 |
|---|---|---|
| `init.sql` | 初始化脚本（容器首次启动自动执行）：建库 `rt`，建三张 MergeTree 表——`metrics_1min`（窗口指标，`ORDER BY window_start`）、`funnel_1min`（漏斗长表，`ORDER BY (window_start, stage)`）、`item_topn_1min`（Top100，`ORDER BY (window_start, cnt)`） | ✅ |

## 五、producer/：数据生产（2 个）

| 文件 | 作用 | 标记 |
|---|---|---|
| `replay_producer.py` | CSV → Kafka 回放器。核心点：**补偿式睡眠**限速（吸收 GC 抖动，长期平均速率贴合目标）、以 `user_id` 作为 Kafka key（同用户进同一分区）、`linger_ms/batch_size/acks` 调优、`--limit` 支持抽样回放 | ✅ |
| `generate_dataset.py` | 没有真实数据时生成同格式模拟数据：多进程分片、时间单调递增、用户/商品/类目呈重尾分布，`--rows` 可扩到亿级 | 🔧 |

## 八、tools/：验证与本地运行（7 个）

| 文件 | 作用 | 标记 |
|---|---|---|
| `sort_dataset.py` | 按事件时间**外部归并排序**（分块 → 落盘 → 多路归并）。回放前必做：原始 CSV 行序是打散的，不排序会丢掉约 96% 记录 | ✅ |
| `native_up.py` | 无 Docker/无 WSL 的一键启动：校验 JDK ≥ 17 → 缺 jar 则构建 → 起 Kafka → 建 topic → 起兼容层/大屏 → 起作业 → 可选回放；日志落 `runtime/logs/`，前台托管可 Ctrl+C 全停 | 🔧 |
| `ch_http_server.py` | ClickHouse HTTP 协议兼容层 + 大屏静态服务（同端口 8090）。底层用 DuckDB 列存，实现 `?query=... FORMAT JSON`、`INSERT ... FORMAT JSONEachRow`、`TRUNCATE`，表带窗口主键做幂等写入 | 🔧 |
| `verify_dataset.py` | 全量扫描原始 CSV：总行数、字段异常、脏时间戳分布、四类行为计数、分钟窗口数（单遍扫描 3.5 GB 约 5 分钟） | 🔧 |
| `compare_windows.py` | 按作业口径离线重算每窗口指标，与 Flink 输出逐窗口 join 对账，输出差异报告 | 🔧 |
| `JobLogicVerifier.java` | 复用作业原有的算子（`MetricsWindowProcess`/`CountAggregate`/`TopNProcess` 等），把 Source 换成 CSV、Sink 换成文件，用于全量验证计算逻辑 | 🔧 |
| `KafkaSourceVerifier.java` | 用真实的 `KafkaSource + UserBehaviorDeserializer` 消费 topic，统计落库条数与丢弃条数，验证生产端字段映射与脏数据过滤 | 🔧 |

## 十、建议的代码阅读顺序

1. `README.md` —— 先搞清指标口径（PV/UV、漏斗、TopN 分别怎么算）
2. `flink-job/.../RealtimeAnalysisJob.java` —— 主干，注释约占 1/3，重点看水位线配置与两条支路
3. `flink-job/.../UserBehaviorDeserializer.java` —— 脏数据处理与"为什么丢弃而不是抛异常"
4. `db/init.sql` —— 三张表的字段与排序键
5. `dashboard/index.html` —— 每条 SQL 对应哪个图表
6. `docker-compose.yml` / `start-all.*` / `tools/native_up.py` —— 最后再看怎么跑起来
